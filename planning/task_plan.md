# Task Plan: 《抓热点》黑客松玩法重构报告

## Goal
产出一份高质量、以**玩法**为核心的重构设计报告：把现有《谁来背锅 / Blame Game》（AI 员工办公室甩锅）改造成
**《AdventureX 抓热点》**——黑客松现场，AI Agent 可扮演「工作人员」或「选手」两大非对称阵营，工作人员抓开热点的选手，
选手必须在工位开热点才能推进项目冲击大奖。本轮只交付**重构报告**，不改代码。

## 新玩法一句话
非对称猫鼠对抗：选手靠"违规开热点"获得带宽 build 项目（进度满→抽取项目属性冲奖），
工作人员靠巡逻+信号探测抓开热点的选手；现场道具 Qoder / 蓝盒子床垫 / INJ token / 狗屎 改变节奏。

## Phases
- [x] Phase 1: 建立规划文件 + 锁定玩法愿景与关键设计问题
- [x] Phase 2: 研究现有引擎/前端契约（可复用点）+ 梳理 AdventureX 梗与道具
- [x] Phase 3: 设计新玩法（双阵营/核心循环/胜负/道具/事件/经济/地图/Agent API）
- [x] Phase 4: 编写重构报告（玩法为主）+ 现有系统→新系统映射与改造清单
- [x] Phase 5: 自查（可玩性/竞争感/确定性/可实现性）并交付

## Key Questions
1. 双阵营如何映射到现有「4 worker + 1 boss + 巡逻」结构？Staff=可控巡逻者，Hacker=选手？几人对几人？
2. 「开热点」机制：热点是暴露信号的双刃剑（推进 build 但被探测）？必须在"工位端点"才计进度？
3. 胜负：Hacker 侧（项目进度→抽属性→冲大奖分）vs Staff 侧（抓到 N 人/累计违规扣分）如何平衡？
4. 四道具 Qoder / 蓝盒子床垫 / INJ token / 狗屎 各自的机制与获取方式？再补几个 AdventureX 梗道具。
5. 两种角色的"不同逻辑代码"——策略沙盒如何暴露 Staff API 与 Hacker API（决策接口差异）？
6. 现有确定性引擎、责任图/甩锅、老板视锥、经济(CP)、链上锚定、供应商徽标——哪些复用/改造/废弃？
7. 项目"属性冲大奖"：进度满后如何选/抽属性（创新/完成度/商业/技术/演示），如何折算成排名分与 rating。

## Decisions Made
- 交付物=报告文档，不改代码（用户明确"先生成报告，重点玩法"）。
